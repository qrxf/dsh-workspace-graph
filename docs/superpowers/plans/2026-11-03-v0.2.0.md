# Workspace Atlas 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship bright status-colored activity, evidence-based memory links and read-only details with current Web/desktop compatibility.
**Architecture:** A read-only SQLite adapter projects continual-evolve data through authenticated native Connection RPC, usable over HTTP and IPC. Memory edges are a render-only overlay. Existing graph/physics contracts remain unchanged.
**Tech Stack:** TypeScript, React, React Flow, node:sqlite, DSH Connection, Playwright.
**Spec:** ../specs/2026-11-03-v0.2.0-design.md

## Global Constraints

- Work only in canonical D:\Project\dsh-workspace-graph; reuse this clean checkout as requested.
- Dragging changes presentation only. Memory lines never enter layout/physics relationships.
- Glow uses the working status color, including current nodes (user clarification).
- No writes or migrations to continual-evolve. Missing store/schema degrades gracefully.
- Verify current latest 0.2.1-rc.5 and rc.4 contracts; do not modify/restart real profiles.

## Review Focus

- Global/local ID collisions must not generate false cross-workspace edges (Task 1).
- Windows spelling normalization must not merge distinct POSIX directories (Task 1).
- Missing database must not create a file, and corrupt schema must not crash graph (Task 1).
- Non-owner/disposed peers must not receive memory data through either transport (Task 1).
- Stale async detail responses must not overwrite a newly selected workspace (Task 2).
